# mono-api-agent

RAG-агент по офіційних OpenAPI-специфікаціях monobank: відповідає на питання
про інтеграцію, спираючись виключно на документацію, і вміє сходити в живий API.

Побудований на тому, що monobank публікує сам — [AI Skills для агентів](https://monobank.ua/api-docs/acquiring/dev/ai-tools/docs--ai-skills)
прямо передбачають власні RAG-системи поверх їхньої документації.

## Що всередині

| Компонент | Рішення |
|---|---|
| Корпус | 25 ендпоїнтів + 45 схем із двох офіційних специфікацій (`personal`, `acquiring`) |
| Ембединги | локальні, `Xenova/multilingual-e5-small` через transformers.js — без ключа й без оплати |
| Пошук | гібридний: косинусна близькість + лексичний збіг |
| Оркестрація | LangGraph з маршрутизацією, самоперевіркою і циклом уточнення |
| Живі дані | публічний `/bank/currency` (єдиний метод без токена) |
| Стійкість | два ланцюжки фолбеку на 9 моделей, запобіжники, деградація до відповіді без моделі |
| Спостережуваність | час, виклики моделі й токени по кожному кроку графа |
| Тести | 219 тестів: юніти, інтеграція фолбеку на моках, межові випадки |

## Граф

```
           ┌─────────┐
  START ──▶│  route  │── питання про курс? ──▶ ┌───────────┐
           └─────────┘                         │ fetchLive │
                │ ні                           └─────┬─────┘
                ▼                                    │
           ┌──────────┐◀───────────────────────────── ┘
           │ retrieve │◀──── уточнений запит ──┐
           └────┬─────┘                        │
                ▼                              │
           ┌──────────┐     ┌────────┐  контексту    │
           │ generate │────▶│ verify │── не вистачає ─┘
           └──────────┘     └───┬────┘
                               │ достатньо
                               ▼
                              END
```

Цикл існує тому, що перший пошук часто промахується на питаннях, сформульованих
не термінами документації — «як брати гроші з картки» замість «invoice create».
Максимум два проходи, інакше на поганому питанні граф крутився б вічно.

## Запуск

```bash
npm install
npm run ingest                  # завантажує специфікації, рахує ембединги (~1 хв)
cp .env.example .env            # і вписати хоча б один ключ

npm run ask -- "як створити рахунок і перевірити, чи його оплатили?" --trace
npm run ask -- "який зараз курс євро?"
```

Без ключа теж працює:

```bash
npm run search -- "як перевірити підпис вебхука"     # лише пошук
MONO_AGENT_FAKE_LLM=1 npm run ask -- "питання" --trace  # хід графа без моделі
npm run bench                                         # заміри моделей-кандидатів
npm test                                              # 219 тестів
```

## Стійкість: відповідь має бути завжди

Безкоштовні пули регулярно віддають 429, провайдер може лежати, ключ може
виявитись недійсним. Жодна з цих подій не повинна дійти до користувача як
«немає відповіді».

**Помилки розрізняються по суті, а не звалені в одну купу:**

| Ситуація | Реакція |
|---|---|
| `401/403` ключ недійсний | провайдер вимикається на весь процес — повторювати безглуздо |
| `404` моделі нема | вимикається саме ця модель |
| `400` запит не прийнято | якщо просили JSON-режим — повтор без нього, інакше далі |
| **`400` завеликий контекст** | **стискаємо запит і повторюємо ТУ САМУ модель** — винен розмір, а не провайдер |
| `429` миттєвий сплеск | пауза з повагою до `Retry-After`, потім повтор |
| **`429` вичерпана денна квота** | **модель знімається з обігу на 6 годин** — за хвилину вона не відновиться |
| `5xx`, мережа, таймаут | експоненційний відкат із джитером |
| порожня відповідь | вважається збоєм, а не відповіддю |
| **помилка в тілі зі статусом `200`** | розпізнається як збій, а не як успіх |
| **HTML замість JSON** | те саме — проксі іноді віддає заглушку з кодом 200 |
| обрив по ліміту токенів | повтор із учетверо більшим бюджетом, до стелі |

### Що ще тримає удар

**Обрізана відповідь не пропадає.** Найповніша з обрізаних запам'ятовується
під час усього проходу. Якщо цілої не дасть ніхто, віддається вона — з чесною
приміткою, що текст неповний. Обрізана на 90% відповідь корисніша за дамп
специфікації, до якого граф падає в самому кінці.

**Роздуми не з'їдають відповідь.** Reasoning-моделі іноді лишають `content`
порожнім і кладуть усе в `reasoning` — такий текст рятується. А блоки
`<think>…</think>` вирізаються перед розбором JSON: усередині роздумів майже
завжди є фігурні дужки, і наївний захват «від першої дужки до останньої»
зшивав роздуми з відповіддю в один невалідний фрагмент.

**Розбір JSON шукає перший збалансований об'єкт**, поважаючи рядки й
екранування, а не покладається на пошук крайніх дужок.

**Стискання контексту ріже з середини.** На початку — найрелевантніші джерела,
у кінці — саме питання; викидається те, що між ними.

**Усі нарощування мають стелю:** бюджет токенів, кількість стискань, глибина
циклу графа, загальний час операції.

Понад це — запобіжник на кожну модель (після двох невдач поспіль вона
випадає з обігу на хвилину) і загальний дедлайн на операцію: ланцюжок із
дев'яти моделей із повторами інакше тривав би хвилини.

**Останній рубіж.** Якщо не відповіла жодна модель із жодного провайдера,
агент не падає, а збирає відповідь із самих знайдених фрагментів специфікації,
чесно попереджаючи, що модель була недоступна. Гірше за згенеровану
відповідь — незрівнянно краще за помилку.

## Чому ланцюжків два

`npm run bench` перевіряє кандидатів на двох реальних задачах графа: строгий
JSON для маршрутизації і грамотна відповідь за контекстом. Виміри показали, що
**це різні вміння**: `openrouter/free` і `gpt-oss-20b:free` відповідають добре,
але JSON стабільно не тримають навіть із `response_format`, а
`inclusionai/ling-3.0-flash` на `response_format` взагалі віддає 400.

Тому ланцюжка два: модель, непридатна для маршрутизації, все ще корисна для
генерації.

**Окрема знахідка — reasoning-моделі.** `nemotron-3-nano` на класифікації з
лімітом 60 токенів витратила 68 на роздуми, впёрлась у стелю
(`finish_reason: length`) і повернула обрізане `{"ne`. Причому в бенчмарку вона
іноді проходила — коли роздуми випадково виявлялися коротшими. Такі моделі
позначені в реєстрі окремо й одразу отримують розширений бюджет.

## Чому самоперевірку робить не модель

Спершу вузол `verify` питав окрему модель, чи спирається відповідь на контекст.
На практиці це виявився найгірший вузол у графі: маленька безкоштовна модель
систематично відповідала «не спирається» на цілком коректні відповіді й
запускала зайвий цикл пошуку.

Заміна на детерміновану перевірку — чи існують згадані у відповіді шляхи
ендпоїнтів у наданому контексті — вирішує ту саму задачу краще, бо галюцинація
в цьому домені майже завжди виглядає саме як вигаданий шлях.

| | LLM-суддя | Детермінована перевірка |
|---|---|---|
| Час проходу | 60,7 с | **19,7 с** |
| Викликів моделі | 5 | **2** |
| Токенів | 19 741 | **6 087** |
| Час вузла verify | 14 914 мс | **1 мс** |

Після того, як у ланцюжку з'явився робочий Groq, той самий прохід займає
**2,8 секунди** — у 22 рази менше за початкові 60,7.

## Пастка, на якій це все ледь не зупинилось

`.env` у цьому проєкті перемагає змінні оточення, і це свідомий відхід від
звичної поведінки dotenv. У шелі був експортований застарілий `GROQ_API_KEY`
рівно тієї ж довжини, що й новий. Файл мовчки програвав йому, кожен запит
отримував 401, і виглядало це як «провайдер зламався», а не як «ключ береться
не звідти». Діагноз коштував двох замінених ключів, жоден з яких не був винен.

Мовчазне затінення конфігурації — найгірший різновид помилки, бо маскується під
чужу. Тому файл має пріоритет, а про кожне перекриття CLI повідомляє вголос.

## Чому пошук саме такий

**Ембединг рахується не по всьому чанку.** Перша версія індексувала повний текст
ендпоїнта, і пошук промахувався: опис методу займає два рядки, а розкрита схема —
сорок, тож вектор описував переважно назви полів. На питання «як створити рахунок»
`invoice/create` не потрапляв навіть у топ-3. Тепер у ембединг іде призначення
методу + імена полів верхнього рівня, а повний текст віддається моделі як контекст.

**Лексичний доданок.** Чисто векторний пошук на цьому корпусі давав дуже щільні
оцінки — усе в межах 0.82–0.87. Модель бачить, що всі 70 чанків про одне платіжне
API, і погано їх розрізняє. Точний збіг слова `invoice`, `statement`, `webhook` —
сильний сигнал, який вектор недооцінює, тож він додається окремо з вагою 0.25.

**Бюджет контексту.** Чанк із повністю розкритими схемами буває під 10 000 символів;
п'ять таких давали 46 000 — дорого й не влазить у менші вікна. Кожен чанк і загальна
сума обрізаються, бюджет витрачається згори вниз.

## Що вимірювалось

| Питання | Топ-1 |
|---|---|
| як створити рахунок і перевірити оплату | `POST /api/merchant/invoice/create` |
| як перевірити підпис вебхука | `GET /api/merchant/pubkey` |
| виписка по картці за минулий місяць | `GET /personal/statement/{account}/{from}/{to}` |

## Тести

```
npm test     # 219 тестів
```

Покрито: розбір `.env`, чанкінг специфікації (рекурсивні `$ref`, `allOf`,
масиви, биті посилання), математика й бюджет пошуку, перевірка заземлення,
метрики, живий інструмент, відповідь без моделі, рішення графа.

Найважливіший блок — інтеграційні тести фолбеку на мокнутому транспорті:
кожен клас помилки, повага до `Retry-After`, розширення бюджету після обриву,
запобіжник і його вистигання, вичерпання дедлайну, повний провал ланцюжка.
Годинник і паузи підмінені, тож набір іде за секунди й не ходить у мережу.

Два дефекти знайшли саме тести: після `401` клієнт продовжував опитувати решту
моделей того самого провайдера, а метрики подвоювали токени, коли вузол з тим
самим іменем траплявся в проході двічі.

## Відомі обмеження

- Питання про **рейт-ліміти** знаходяться погано: ліміти згадані всередині описів
  окремих методів, а не винесені в окрему сутність. Потрібен окремий чанк
  із загальних правил API.
- Лексичний доданок іноді підіймає не той чанк: у питанні «вебхук від monobank»
  слово `bank` тягне вгору `/bank/currency`. Правильний ендпоїнт лишається в
  топі, але не першим.
- Корпус — **лише специфікації**. Гайди, приклади коду й опис ECDSA-верифікації
  вебхуків живуть в іншому місці документації і поки не індексуються.
- Крос-мовність не ідеальна: документація українською, і питання російською
  ранжуються трохи гірше за україномовні.
- `/bank/currency` лімітований одним запитом на 60 секунд — відповідь кешується,
  тому курс може бути до хвилини несвіжим.
